# עוזר באתר: בדיקת היתכנות ואפיון

סטטוס: טיוטה לאישור מנשה (28.11). מעקב: issue #203.

## 1. השורה התחתונה

אפשר, ובלי שרת חדש. העוזר הוא Edge Function אחת ב-Supabase שמדברת עם Claude.
כל שאלה וכל פעולה רצות **בשם המשתמש המחובר**, עם אותו מפתח כניסה שלו, ולכן אותן הרשאות RLS
ואותן בדיקות תפקיד שכבר קיימות במסד הנתונים חלות גם על העוזר. העוזר לא יכול לראות או לעשות
משהו שהמשתמש עצמו לא יכול לעשות במסך.

שני עקרונות שלא משתנים:

1. **עונה רק ממה שיש באתר.** אין חיפוש באינטרנט. כל תשובה נשענת על תוצאה של כלי (שאילתה למסד
   הנתונים או קטע מחבילת ההסברים), ומפנה לדף באתר. אם אין מידע, העוזר אומר "אין לי את זה באתר".
2. **פעולה שמשנה משהו לא מתבצעת בלי לחיצה של המשתמש.** העוזר רק מכין את הפעולה ומציג כרטיס
   "לאשר?". הלחיצה קוראת לאותה פונקציה שהכפתור הרגיל במסך קורא לה.

## 2. מה העוזר יודע

| מקור | דוגמאות לשאלות | איך מגיעים אליו |
| --- | --- | --- |
| נתוני האתר | "מי היועצים בתחום תנועה?", "האם לספק X יש מאגר בתוקף?" | הפונקציות הקיימות: `catalog_snapshot`, `supplier_detail`, `registry_review` ועוד |
| חישובים | "באיזה הליך צריך להתקשר על 300,000 ₪?" | Edge Function `route-check` והספים החודשיים |
| העבודה שלי | "מה מחכה לי?", "מה קרה עם הבקשה שלי?" | `home_overview`, `admin_overview`, `portal_me` |
| הסברים על האתר והנוהל | "איך מוסיפים ספק?", "מה ההבדל בין מאגר שלנו למאגר העירייה?" | חבילת הסברים בעברית (סעיף 5) |

הרשימה המלאה של הכלים לכל תפקיד נקבעת בשרת, לפי `private.has_role`. משתמש צופה לא מקבל בכלל את
כלי הניהול, כך שהמודל לא יודע שהם קיימים.

## 3. ארכיטקטורה

```
דפדפן (חלונית צד)  ──JWT של המשתמש──▶  Edge Function: assistant
                                          │  1. בודק כניסה ומכסה יומית
                                          │  2. בונה רשימת כלים לפי התפקיד
                                          │  3. לולאה מול Claude API (streaming)
                                          │  4. כל כלי = קריאה ל-RPC עם ה-JWT של המשתמש
                                          ▼
                                   Postgres + RLS (בלי מפתח secret)
```

- **שרת:** Edge Function חדשה `supabase/functions/assistant/`, ב-TypeScript (Deno), עם
  `@anthropic-ai/sdk`. הלוגיקה ב-`_shared/assistant/`, לפי תקן הקוד.
- **מפתח:** `ANTHROPIC_API_KEY` כ-secret של Supabase בלבד. לא בדפדפן ולא בריפו.
- **הרשאות:** הפונקציה יוצרת לקוח Supabase עם ה-Authorization של המשתמש, **לא** עם מפתח secret.
  כך כל קריאה עוברת את אותה RLS. זו נקודת האבטחה המרכזית, ויש לה בדיקה ייעודית.
- **ממשק:** כפתור "שאל את העוזר" בכותרת, שפותח חלונית צד (במובייל: גיליון מלמטה). התשובה נכתבת
  תוך כדי (streaming), עם קישורים לדפים באתר. לפי `DESIGN.md` ואבני הבניין הקיימות.
- **פעולה:** כשהמודל מציע פעולה, הוא קורא לכלי `propose_action` שמחזיר כרטיס עם תיאור בעברית
  ופרטי הקריאה. הדפדפן מציג "לאשר / לבטל". "לאשר" קורא ל-RPC הרגיל (למשל `set_supplier_status`),
  ולא דרך המודל.

### למה לא Managed Agents

Anthropic מציעה גם סוכן מנוהל שרץ אצלה. כאן הוא לא מתאים: הכלים חייבים לרוץ בתוך Supabase עם ה-JWT
של המשתמש, תוכנית הארכיטקטורה קובעת ש-Supabase הוא השרת היחיד, והשיחות קצרות (שאלה ותשובה).
קריאה ישירה ל-Messages API עם לולאת כלים פשוטה בתוך ה-Edge Function זולה ופשוטה יותר.

## 4. אבטחה

| סיכון | הגנה |
| --- | --- |
| העוזר רואה מידע שאסור למשתמש | כל כלי רץ עם JWT של המשתמש, אותה RLS. בדיקה: צופה שואל על נתון של מנהל ומקבל "אין הרשאה" |
| העוזר מבצע פעולה בלי שהמשתמש התכוון | פעולות כתיבה רק דרך כרטיס אישור ולחיצה. המודל לא מחזיק כלי כתיבה בכלל |
| "הזרקת הוראות" דרך טקסט שספק הקליד (שם, תיאור) | תוצאות כלים מסומנות כנתונים, לא הוראות; ובגלל השורה הקודמת, גם הוראה זדונית לא יכולה לבצע כלום |
| ספק רואה ספקים אחרים | לספקים יש סט כלים נפרד (`portal_*`) שמוגבל לחשבון שלהם |
| עלות שבורחת | מכסה יומית למשתמש ותקרה חודשית לאתר, נבדקות בשרת לפני כל קריאה |
| דליפת מפתח | המפתח רק ב-secrets של Supabase |
| המודל ממציא תשובה | הנחיה לענות רק מתוצאות כלים, עם קישור למקור; סט בדיקה של שאלות שאין להן תשובה באתר |

כל שינוי בהרשאות או ב-Edge Function עובר `security-audit` לפי מפת הסקילים.

### רישום

טבלה חדשה `assistant_turns`: מי שאל, מתי, אילו כלים נקראו, כמה טוקנים ועלות. המשתמש רואה רק את
שלו (RLS); מנהל רואה סיכומים במסך השימוש (`/usage`). תוכן השאלות נשמר לזמן מוגבל (החלטה 5).

## 5. חבילת ההסברים

היום אין באתר טקסט עזרה למשתמשים. המסמכים ב-`documentation/` נכתבו לפיתוח. לכן שלב 0 כותב חבילה
קצרה בעברית (בערך 30 עד 60 נושאים: איך עושים כל דבר במסך, מה אומר כל סטטוס, עיקרי הנוהל והתקנות),
על בסיס `screens-spec-he.md`, `procurement-engine-he.md` ו-`legal-research-he.md`.

החבילה קטנה (פחות מ-50 אלף תווים), ולכן בשלב הראשון היא נכנסת כולה להנחיית המערכת עם prompt
caching. אין צורך במסד וקטורים. אם תגדל מאוד, עוברים לחיפוש טקסט ב-Postgres.

אותה חבילה יכולה לשמש גם כדפי עזרה רגילים באתר.

## 6. עלות

מחירי Claude API לכל מיליון טוקנים (נכון ל-11.2026):

| מודל | קלט | פלט | מתאים ל |
| --- | --- | --- | --- |
| Claude Haiku 5.5 | $0.10 | $0.50 | שאלות ותשובות פשוטות |
| Claude Sonnet 5.5 | $2 | $10 | שאלות מורכבות, בחירת כלים, הכנת פעולות |
| Claude Opus 5.5 | $4 | $20 | לא נדרש כאן |

הערכה לשאלה ממוצעת: כ-15 אלף טוקנים קלט (רובם הנחיה שמורה במטמון) וכ-700 טוקנים פלט.

| מודל | לשאלה | 1,000 שאלות בחודש | 10,000 שאלות בחודש |
| --- | --- | --- | --- |
| Haiku 5.5 | פחות מ-0.01 ₪ | כ-3 ₪ | כ-25 ₪ |
| Sonnet 5.5 | כ-0.05 ₪ | כ-50 ₪ | כ-500 ₪ |

אלה הערכות. המספרים האמיתיים יימדדו בשלב 0 על שאלות אמיתיות, לפני שבוחרים מודל.
עלות Supabase לא משתנה (Edge Function אחת נוספת).
