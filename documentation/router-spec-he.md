# אפיון ניהול הראוטר באתר

גרסה 1, 28.11.2026. משימה: issue #205. מתואם עם אפיון בר הניווט (`navigation-spec-he.md`), שקורא את
אותם נתוני נתיב.

## 1. במשפט אחד

הראוטר הקיים עובד, אבל המידע על כל מסך (כתובת, כותרת, אזור בתפריט, מי רשאי להיכנס) כתוב היום
בשלושה ועד ארבעה מקומות שונים, וכבר נפרד. האפיון מאחד אותו לטבלת נתיבים אחת, מוסיף בדיקת הרשאה
אחת לפני כל מסך, וסוגר כמה פערים קטנים (404 באזור הספקים, חזרה לאותו מקום בגלילה, קישורים שבורים).

## 2. מה קיים היום ועובד

| נושא | איך זה עובד היום | קובץ |
| --- | --- | --- |
| סוג הראוטר | React Router 8.5 במצב ספרייה, `createHashRouter`. כתובות בצורה `#/supplier/123` | `app-shell/router.tsx` |
| טעינה עצלה | כל מסך נטען ב-`lazy` רק כשנכנסים אליו | `app-shell/routes.tsx` |
| שגיאות | לכל מסך `errorElement` משלו, ולשורש `RouteError`. מסך אחד שנופל לא מפיל את האתר | `screen-error.tsx`, `route-error.tsx` |
| כותרת ופוקוס | כל נתיב נותן `handle.title`; ה-Layout מעדכן את `<title>` ומעביר פוקוס ל-`h1` | `layout.tsx` |
| קישור ישיר | כל כתובת נפתחת ישירות. מי שלא מחובר נשלח לכניסה עם `next`, וחוזר לאותו מסך | `session-watch.ts` |
| 404 | נתיב `*` מציג "הדף לא נמצא" | `not-found-page.tsx` |
| כתובת ישנה | `/route-check` מפנה ל-`/engagement` | `routes.tsx` |
| שני אזורים | אתר העובדים, ו-`/supplier-area` עם מסגרת משלו בלי לשוניות העובדים | `supplier-area-layout.tsx` |

ההחלטה על hash (החלטה 0006) נשארת: GitHub Pages לא מחזיר את הדף לכתובת עמוקה. ראו החלטה א בסעיף 7.

## 3. הפערים

1. **אותו מידע בכמה מקומות.** לכל מסך ניהול:
   - הכתובת והכותרת ב-`routes.tsx`;
   - התפקידים ב-`screens.ts` (לכרטיסי מסך הניהול ולהודעת "אין הרשאה");
   - שוב התפקידים ב-`requireRoles([...])` בתוך ה-api של המסך;
   - האזור בתפריט ברשימה נפרדת ב-`sections.ts`.
2. **הרשימות כבר נפרדו (באג חי).** `sectionOf` לא מכיר את `/addresses`, `/supplier-links`, `/usage`
   ו-`/errors`. במסכים האלה לשונית "ניהול" לא מסומנת, אף שהם מסכי ניהול לכל דבר.
3. **בדיקת ההרשאה מפוזרת.** כל loader בודק תפקיד בעצמו, ב-12 קבצים. מסך חדש שישכח את הבדיקה יציג
   שגיאת מסד גולמית במקום "אין לך הרשאה". המסד עדיין חוסם, כך שאין כאן פרצה, אבל ההודעה שגויה.
4. **404 באזור הספקים.** כתובת כמו `#/supplier-area/xyz` נופלת ל-404 של אתר העובדים, וספק רואה את
   לשוניות העובדים.
5. **ספק שלא נמצא.** `#/supplier/999` זורק 404 מה-loader, אבל `ScreenError` מציג "לא ניתן להציג את
   המסך" במקום "הספק לא נמצא".
6. **חזרה לרשימה מאבדת את המקום.** אין `ScrollRestoration`. מי שגולל בקטלוג, נכנס לספק וחזר, חוזר
   לראש הרשימה.
7. **קישורים כטקסט חופשי.** כ-30 קישורים כתובים ידנית (`to="/catalog"`, `` to={`/supplier/${id}`} ``).
   שינוי כתובת לא ייתפס בבדיקות.
8. **`routes.tsx` מתקרב למגבלה.** 241 שורות מתוך 300, וכל מסך חדש מוסיף 9.

## 4. התוכנית

### 4.1 טבלת נתיבים אחת

קובץ חדש `app-shell/route-table.ts` מחזיק שורה אחת לכל מסך. `routes.tsx` בונה ממנה את אובייקטי
הנתיב, ולא כותב אותם ביד.

```ts
export interface RouteHandle {
  title: string;                 // כותרת הלשונית והקורא-מסך
  section: SectionKey | null;    // 'home' | 'catalog' | 'requests' | 'admin'; null = מחוץ לתפריט
  roles?: readonly Role[];       // מי רשאי, בנוסף למנהל מערכת. בלי השדה: כל משתמש
  navLabel?: string;             // שם קצר לתפריט, כשהוא שונה מהכותרת (אפיון בר הניווט)
}

interface ScreenRoute {
  id: string;                    // 'users', 'supplier' ...
  path: string;                  // 'users', 'supplier/:id'
  handle: RouteHandle;
  load: () => Promise<ScreenModule>;   // ה-import העצל של המסך
}
```

מי קורא ממנה:

- `routes.tsx`: בונה את הנתיבים, כולל `errorElement` ו-`lazy` לכל אחד.
- `sections.ts`: `sectionOf` מוצא את הנתיב התואם ומחזיר את `handle.section`. רשימות הנתיבים
  הידניות נמחקות (מתקן את פער 2).
- `screens.ts`: כרטיסי מסך הניהול שומרים רק תיאור, קבוצה ומונה ממתינים, ומפנים לשורה בטבלה לפי
  `id`. הכתובת והתפקידים נלקחים מהטבלה. `audienceOf` קורא את `handle.roles`.
- אפיון בר הניווט קורא `section` ו-`navLabel`.

כתובות ישנות (היום רק `/route-check`) נכנסות לרשימת הפניות קצרה באותו קובץ.

### 4.2 בדיקת הרשאה אחת, לפני המסך

נתיב האב של אתר העובדים מקבל `middleware` (יציב ב-React Router 8). לפני כל מעבר הוא לוקח את
`handle.roles` של הנתיב התואם, קורא ל-`identity()` ובודק עם `permitted`. אין הרשאה: זורק 403,
ו-`ScreenError` מציג את ההודעה הקיימת "אין לך הרשאה למסך הזה". לא מחובר: 401 ומעבר לכניסה עם
`next`, כמו היום.

- `requireRoles` יוצא מה-loaders. מי שצריך את זהות המשתמש (`users`, `categories`) קורא ל-`identity()`,
  שכבר משתף בקשה אחת בין כל הקוראים.
- הבדיקה בדפדפן היא נוחות בלבד. ההרשאה האמיתית נשארת ב-RLS ובפונקציות המסד, בלי שינוי.
- בדיקה אוטומטית עוברת על הטבלה: לכל נתיב עם `roles`, משתמש בלי התפקיד מקבל 403 ומשתמש עם התפקיד
  נכנס. בדיקה שנייה משווה את `roles` בטבלה לתפקידים שהמסד דורש (לפי רשימה קבועה בבדיקה), כדי שלא
  ייפרדו שוב.

### 4.3 קישורים בטוחים

- `app-shell/paths.ts` מייצא פונקציות לכתובות עם פרמטר, למשל `supplierPath(id)` ו-`registryPath(v)`,
  דרך `generatePath` של React Router.
- בדיקה שסורקת את קבצי `web/src` ומוודאת שכל `to="/..."` קבוע תואם נתיב בטבלה (`matchRoutes`).
  קישור שבור נכשל ב-CI.

### 4.4 מסכי "לא נמצא"

- `ScreenError`: סטטוס 404 מציג "לא נמצא" עם הסבר לפי המסך (`supplier`: "הספק לא נמצא. ייתכן שהוסר
  או שהקישור ישן"), וקישור לקטלוג.
- `/supplier-area` מקבל נתיב `*` משלו, בתוך מסגרת הספקים, עם קישור לאזור האישי (פער 4).

### 4.5 חזרה לאותו מקום

- `<ScrollRestoration />` ב-Layout של העובדים ושל הספקים.
- המפתח הוא הכתובת (`getKey` לפי `pathname + search`), כך שחזרה לקטלוג חוזרת לאותה נקודה.
- סיכון: הקטלוג מצייר כרטיסים בחלקים. אם הגלילה משוחזרת לפני שהכרטיסים צוירו, היא תיעצר באמצע.
  בדיקת e2e: לגלול, להיכנס לספק, לחזור, ולוודא שהכרטיס שנלחץ נראה במסך. אם היא נכשלת, הקטלוג
  שומר את מיקומו בעצמו ומשחזר אחרי הציור.

### 4.6 טעינה מראש בכוונה

כשהעכבר עומד על קישור בתפריט, או כשהוא מקבל פוקוס, מתחילה הורדת הקוד של המסך (`load()` מהטבלה).
הנתונים לא נטענים מראש, רק הקוד. כך המעבר מרגיש מיידי בלי בקשות מיותרות למסד.

- התקציב: הטעינה הראשונה עומדת על הקצה (ראו `react-guide-he.md` 6). ה-helper קטן, אבל אם הוא חורג
  מהתקציב, השלב הזה נדחה.

### 4.7 מה לא משתנה

- כתובות המסכים, כולל `/admin`. קישורים שנשלחו במייל ממשיכים לעבוד.
- כניסה עם `next`, טיפול בחזרה מההתחברות ב-`main.tsx`, מעקב שימוש וזמני טעינה.
- טיוטות טפסים נשמרות כבר ב-`sessionStorage`, ולכן אין צורך בחסימת יציאה ממסך (`useBlocker`).

## 6. איך יודעים שזה עובד

- מוסיפים מסך חדש בשורה אחת בטבלה, והוא מקבל כותרת, לשונית מסומנת, הרשאה וכרטיס בלי לגעת בקובץ אחר.
- לשונית "ניהול" מסומנת בכל מסכי הניהול, כולל `/addresses`, `/supplier-links`, `/usage`, `/errors`.
- משתמש בתפקיד צופה שפותח `#/users` רואה "אין לך הרשאה", לא שגיאת מסד.
- `#/supplier/999` מציג "הספק לא נמצא". `#/supplier-area/xyz` מציג 404 בלי לשוניות העובדים.
- חזרה מכרטיס ספק לקטלוג מחזירה לאותו מקום.
- `npm run check` ירוק, כולל תקציב הטעינה.

## 7. החלטות של מנשה

**א. צורת הכתובות.** להשאיר `#/supplier/123` (מומלץ), או לעבור לכתובות נקיות `/supplier/123`.
כתובת נקייה נראית טוב יותר בקישור, אבל ב-GitHub Pages היא דורשת עקיפה (קובץ 404 שמפנה חזרה לאתר),
ששוברת קישורים ישנים אם לא מטפלים בהם, ומאטה את הכניסה הראשונה. ההמלצה: להשאיר hash עד שהאתר
יעבור לאירוח שתומך בזה.

**ב. חיפוש בקטלוג בתוך הכתובת.** היום חיפוש וסינון בקטלוג לא נשמרים בכתובת, ולכן אי אפשר לשלוח
למישהו קישור לחיפוש. אפשר להוסיף, אבל זה שינוי במסך הקטלוג ולא בראוטר. ההמלצה: לא בשלב הזה, ולשקול
יחד עם אפיון כרטיסי הספקים.
